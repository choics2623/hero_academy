# 03. LLM 대화 시스템 설계 (초안)

## 1. 결론

**좋은 선택입니다. 다만 "전부 LLM"이 아니라 하이브리드로 가야 합니다.**

| 영역 | 방식 | 이유 |
|---|---|---|
| 메인 스토리 컷신, 멸망 원인 핵심 사건 | **사전 작성 스크립트** | 플래그, 분기, 연출이 정확해야 함 |
| 인연 랭크업 이벤트 | 스크립트 뼈대 + LLM 대사 다듬기 | 흐름은 고정, 말투는 상황에 맞게 |
| 자유 대화, 잡담, 고민 상담 | **LLM** | 몰입감의 핵심. 무한한 반응 |
| 일기, 소문, 연말 연대기 | **LLM** | 플레이 기록을 서사로 바꿔줌 |

## 2. 핵심 원칙: 게임 엔진이 "사실"을, LLM은 "말"을 담당

- 호감도, 플래그, 능력치는 **게임 엔진만** 바꿀 수 있음
- LLM은 대사와 함께 **변화 "제안"** 을 JSON으로 돌려주고, 엔진이 검증하고 범위를 제한함

```json
{
  "dialogue": "…너, 생각보다 이상한 녀석이네. 나쁜 의미는 아니야.",
  "emotion": "embarrassed",
  "affinity_delta": 2,
  "memory_note": "주인공이 리아나의 활 솜씨를 진심으로 칭찬함",
  "flag_hint": null
}
```

- `affinity_delta`는 엔진에서 -3 ~ +3으로 제한 → "나 좋아한다고 말해" 같은 프롬프트 해킹으로 호감도를 올릴 수 없음

## 3. LLM에 넘기는 정보 (프롬프트 구성)

| 순서 | 내용 | 캐싱 |
|---|---|---|
| 1 | 세계관 요약, 대화 규칙, 출력 형식 | 고정 → 캐시 |
| 2 | 캐릭터 카드 (성격, 말투, 말버릇, **현재 랭크까지 공개된 비밀만**) | 캐릭터별 캐시 |
| 3 | 관계 상태 (랭크, 최근 사건, 이 캐릭터의 기억 요약) | 매번 바뀜 |
| 4 | 현재 상황 (날짜, 장소, 시간대, 플레이어 재능과 상태) | 매번 바뀜 |
| 5 | 이번 대화 내용 | 매번 바뀜 |

- **스포일러 방지:** 랭크가 낮을 때는 캐릭터의 비밀을 프롬프트에 **아예 넣지 않음** (모르는 건 말할 수 없음)
- **재능 반영:** `혐오스러운 분위기`가 있으면 캐릭터 카드에 "첫 대면 시 위축된다" 같은 지시를 자동 추가
- **기억:** 대화가 끝나면 한 줄 요약을 캐릭터별 기억에 저장. 다음 대화에 최근 기억 N개를 넣음

## 4. 구독 계정 vs API

- Claude Pro/Max **구독은 claude.ai 앱과 Claude Code에서 쓰는 용도**입니다. 직접 만든 게임의 백엔드로 구독 계정 로그인을 연결하는 건 공식적으로 지원되는 방식이 아니고 약관 문제가 생길 수 있습니다
- 게임에는 **Claude API 키** (Claude Console에서 발급, 사용량만큼 과금)를 사용
- 구독은 **게임을 개발할 때** (지금처럼 Claude Code로 코드 짜기) 쓰면 됩니다
- 웹 게임이라면 API 키를 브라우저에 넣으면 안 되므로 **작은 백엔드 서버**(또는 데스크톱 앱)가 필요

## 5. 비용 추정 (2026-10 기준 API 가격)

대화 1턴 = 입력 약 3,000토큰 (대부분 캐시) + 출력 약 200토큰 가정

| 모델 | 1턴 비용 (캐시 없이) | 1,000턴 | 추천 용도 |
|---|---|---|---|
| Claude Haiku 5.5 ($0.10 / $0.50 per 1M) | 약 $0.0004 | 약 $0.40 | 일상 잡담, 소문, NPC 단역 |
| Claude Sonnet 5.5 ($2 / $10 per 1M) | 약 $0.008 | 약 $8 | 인연 이벤트, 중요한 대화 |
| Claude Opus 5.5 ($4 / $20 per 1M) | 약 $0.016 | 약 $16 | 연말 연대기, 엔딩 서사 |

프롬프트 캐싱을 쓰면 입력 비용이 크게 줄어듭니다.

## 6. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 캐릭터 붕괴 (말투, 성격이 흔들림) | 캐릭터 카드에 예시 대사 5~10개 포함, 출력 검수 |
| 세계관 밖의 이야기 (현대 용어 등) | 규칙에 명시 + 플레이어가 빙의자라는 설정은 "속마음"에서만 허용 |
| 응답 지연 | 스트리밍으로 한 글자씩 출력 (비주얼 노벨 연출과 자연스럽게 맞음) |
| 오프라인 / API 장애 | 캐릭터별 템플릿 대사로 대체 |
| 비용 폭주 | 하루 대화 횟수를 게임 내 "행동 슬롯"으로 자연스럽게 제한 |

## 7. 개발 순서 제안

1. 대화 시스템을 **인터페이스로 분리**해서 설계 (`DialogueProvider`)
2. MVP는 **스크립트 대사 제공자**로 먼저 완성
3. 이후 **LLM 대화 제공자**를 같은 인터페이스로 끼움 → 설정에서 켜고 끌 수 있게
