# 06. 엔진 설계 & 작가 가이드

> 「멸망까지 10년」 스토리 엔진 v0.1
> TypeScript, 콘텐츠는 전부 `content/` 폴더의 YAML

---

## 1. 해결하려는 문제

분기형 스토리는 볼륨이 커지면 세 가지가 무너진다.

| 문제 | 증상 | 이 엔진의 해법 |
|---|---|---|
| **분기 폭발** | 선택지 하나 늘릴 때마다 경우의 수가 곱해짐 | ① 스토리렛 + "가장 구체적인 것이 이긴다" |
| **일관성 붕괴** | 오타 난 플래그, 영원히 안 열리는 이벤트, 회수 안 된 복선 | ② 의존성 그래프 기반 정적 분석 (린트) |
| **도달 가능성 불명** | "이 엔딩, 진짜 볼 수 있긴 해?"를 사람이 확인할 수 없음 | ③ 몬테카를로 플레이테스터 + ④ 목표 역추적 탐색기 |

그리고 이 게임 고유의 요구 사항 하나:

| 요구 | 해법 |
|---|---|
| 원작 붕괴도, 공략 노트의 신뢰도 | ⑤ "원작은 기본값" 모델: 붕괴도와 노트 신뢰도를 **자동 계산** |

## 2. 핵심 아이디어

### ① 스토리렛 + 가장 구체적인 것이 이긴다
- 이벤트는 트리가 아니라 **독립된 조각(스토리렛)** 이다. 각자 "언제, 어떤 조건에서 일어나는지"만 선언한다
- 같은 활동에 여러 스토리렛이 걸려 있으면, 조건이 맞는 것 중 **조건이 가장 많은(구체적인) 것**이 선택된다
- 대사 변형도 같은 규칙이다

```yaml
- 나레이션:
    - "오늘의 메뉴는 감자 스튜다."                                    # 기본
    - { when: "talent.혐오스러운분위기", text: "아주머니가 국자를 떨어뜨렸다." }
    - { when: "talent.악명높은가문 and fate.edric == 'alive'", text: "누군가 옆에 앉았다." }
```

**효과:** 작가는 기존 장면을 고치지 않고 **특수 상황용 변형을 덧붙이기만** 하면 된다. 분량이 곱이 아니라 **합**으로 늘어난다.

### ② 의존성 그래프 + 정적 분석
엔진은 모든 조건식과 효과식을 파싱해서 "어떤 변수를 누가 언제 쓰고, 누가 언제 읽는가"의 그래프를 만든다. 이걸로 플레이하지 않고도 다음을 잡는다.

| 검사 | 예 |
|---|---|
| 오타 난 변수 | `affinty.liana` → 쓰는 곳이 없음 |
| 오타 난 값 | `fate.sera == 'savd'` → 이 값은 대입되는 곳이 없음 (가능한 값: saved, saved_quiet, dropped) |
| **시간 데이터 흐름** | 3월 이벤트의 조건 `flag.y`가 4월에야 쓰임 → 절대 발생하지 않음 |
| 복선 순서 | 회수가 심기보다 항상 먼저 일어남 |
| 갈림길 | 바꿀 수 있는 이벤트가 마감 이후에만 있음 |
| 고아 이벤트, 없는 다음 이벤트, 화자 이름 오타, 파생 변수 순환 | |

### ③ 몬테카를로 플레이테스터
무작위 캐릭터로 수천 번 자동 플레이한다 (3,000회에 약 3초).
- `curious` 정책: 지금까지 덜 본 이벤트·선택지 쪽으로 가려고 해서 커버리지가 빨리 오른다
- 리포트: 한 번도 발생하지 않은 이벤트, **한 번도 보이지 않은 선택지**, 갈림길 결과 분포, 복선 회수율, "복선을 못 보고 회수 장면을 본" 비율

> 실제로 개발 중 `liana_stairs`의 세 번째 선택지가 **구조적으로 절대 보일 수 없다**는 걸 이 도구가 찾아냈다 (호감도 20에 도달하려면 반드시 거치는 이벤트가 그 선택지를 숨기는 플래그를 켜고 있었음).

### ④ 목표 역추적 탐색기
"`fate.liana == 'awakened'`에 도달할 수 있는가? 있다면 어떻게?"를 자동으로 답한다.

**알고리즘: 빔 탐색 + 역추적 휴리스틱**
1. 목표 조건을 원자 조건으로 쪼갠다
2. 아직 거짓인 원자마다, 의존성 그래프에서 **그 변수를 목표 쪽으로 움직이는 쓰기**를 찾는다
3. 그 쓰기가 일어나려면 필요한 조건까지 **재귀적으로(깊이 2)** 거리를 잰다
   - 수치 조건은 모자란 만큼 비례해서 거리를 준다 (호감도 15/40이 0/40보다 가깝다)
4. 도와줄 수 있는 이벤트가 **전부 마감됐으면** 그 상태는 죽은 상태 → 가지치기
5. 빔(기본 24개)에 가장 유망한 상태만 남기고 다음 결정으로

**효과:** 아직 결과는 안 바뀌었지만 **필요한 조건에 다가가는 행동**(예: 원예부 가입 → 온실 방문 → 호감도 상승)을 우선 탐색한다. 실패하면 무엇이 막는지 설명한다.

```
❌ 이 빌드로는 도달하지 못함. 막고 있는 것:
  • secret.liana == 1  (현재 secret.liana = null)
      - 이벤트:liana_stairs.choices[2]: 조건 미달: affinity.liana >= 20 [현재 affinity.liana=5]
```

`npm run verify`는 이걸 이용해 **모든 갈림길의 모든 결과가 어떤 빌드로든 도달 가능한지** 자동 증명한다.

### ⑤ "원작은 기본값" 모델
- 갈림길(crossroad)마다 **원작 값(canon)과 마감**을 선언한다
- 마감까지 아무도 그 값을 정하지 않으면 엔진이 **원작 값으로 자동 확정**하고 원작 이벤트(예: 사망 소식)를 띄운다
- 그래서 **원작 그림자 세계를 따로 시뮬레이션할 필요가 없다**
  - 원작 붕괴도 = 원작 값과 달라진 갈림길들의 가중치 합 (자동)
  - 공략 노트는 `about: [갈림길]`만 적어두면, 그 갈림길이 원작과 달라지는 순간 자동으로 "⚠ 신뢰할 수 없음"이 된다
  - `fragile: 10` → 붕괴도가 10%를 넘으면 신뢰 불가 / `valid_while: 조건` → 조건이 깨지면 신뢰 불가

## 3. 구조

```
content/                 ← 작가가 쓰는 곳 (YAML)
  rules.yaml             달력, 능력치, 훅, 기억 풍화 공식
  talents.yaml origins.yaml perks.yaml
  activities.yaml        슬롯마다 고르는 행동
  crossroads.yaml        갈림길 (원작 값 + 마감)
  notes.yaml             공략 노트
  foreshadows.yaml       복선
  derived.yaml           파생 변수 (읽을 때 계산)
  characters.yaml        캐릭터 (화자 이름 검사용)
  events/*.yaml          스토리렛

src/engine/              ← 런타임 (브라우저에서도 동작하도록 fs 의존 없음, load.ts만 Node 전용)
  expr.ts                조건식/효과식 언어 + 분석 (refs, 구체성, 거리)
  time.ts                달력 (학년은 3월 시작)
  content.ts             YAML → 검증 → 컴파일
  world.ts               상태(평평한 변수 사전), 붕괴도, 노트 신뢰도
  text.ts                대사 변형 선택, {{템플릿}}
  creation.ts            캐릭터 생성 규칙
  game.ts                진행 루프

src/analysis/            ← 작가용 도구
  graph.ts               의존성 그래프
  lint.ts                정적 분석
  simulate.ts            몬테카를로 플레이테스터
  seek.ts                목표 역추적 탐색기

src/tools/               ← CLI
```

### 상태 모델
모든 상태는 평평한 변수 사전 하나다.

| 네임스페이스 | 예 | 누가 씀 |
|---|---|---|
| `stat.*` | `stat.근력` | 생성, 활동, 이벤트 (성장률 `growth.*` 자동 적용) |
| `affinity.*` `trust.*` `mood.*` `secret.*` | `affinity.liana` | 이벤트 |
| `fate.*` | `fate.sera` | 이벤트 / 마감 시 원작 값 |
| `talent.*` `perk.*` `origin` | `talent.병약` | 생성 (개화 시 이벤트가 레벨 변경) |
| `fired.*` `count.*` | `fired.y1_exam`, `count.훈련장` | 엔진 자동 |
| `fs.*` | `fs.F04.noticed` | 엔진 자동 (plants/pays) |
| `note.*` | `note.note_sera.known` | 엔진 자동 |
| 가상 변수 | `world.collapse` `time.month` `time.slot` `time.roll` | 엔진이 계산 |

평평하게 두면 복제(탐색), 비교(붕괴도), 해시(중복 제거), 분석(린트)이 전부 단순해진다.

### 한 슬롯의 흐름
```
슬롯 시작 ─ 대기 중인 원작 이벤트? ─ 강제 이벤트(on: auto)? ─ 활동 선택
                                                          │
                       활동 효과 → 그 활동의 스토리렛 중 가장 구체적인 것
                                                          │
         장면: 대사 렌더 → 효과 → 복선 → 판정(check) → 분기(branch) → 선택지 / next
                                                          │
슬롯 종료 ─ 훅 ─ 시간 진행 ─ 마감된 갈림길은 원작 값으로 확정 ─ 다음 슬롯
```

## 4. 작가 가이드

### 이벤트 (스토리렛)
```yaml
- id: liana_stairs             # 필수, 전체에서 유일
  title: 계단의 리아나
  on: 온실                     # 활동 id (여러 개면 [a, b]) / auto = 강제 이벤트 / 생략 = next로만 도달
  window: "1.6"                # 또는 at: "1.6.1.방과후" / window: { from: "1.4", to: "1.6" }
  slots: [밤]                  # 특정 슬롯에만
  when: "affinity.liana >= 20" # 발생 조건
  priority: 1                  # 구체성보다 우선하는 순위 (기본 0)
  repeat: true                 # 반복 가능 (숫자면 최대 횟수, 기본 1회)
  free: true                   # 슬롯을 소모하지 않음 (auto 이벤트용)
  lines: [...]
  effects: ["affinity.liana += 3", "mood.liana.불안 = 1"]
  plants: [{ id: F05, notice: { value: "stat.지성 + 25 * talent.직감", dc: 28 } }]
  pays: [F04]
  check: { value: "stat.근력 + luck", dc: 30 }   # 값 + d20 >= dc
  success: { lines: [...], effects: [...] }
  fail: { lines: [...] }
  branch:                      # 조건 맞는 것 중 가장 구체적인 하나
    - { when: "origin == '악역도련님'", next: lab_edric_self }
    - { next: lab_edric_other }
  choices:
    - text: 보건실에 같이 가자고 한다
      when: "know.moonherb"          # 안 맞으면 선택지가 안 보임
      requires: "stat.매력 >= 14"    # 안 맞으면 🔒로 보임
      hint: 아렌은 이 기연을 얻지 못하게 된다
      effects: [...]
      lines: [...]
      next: other_event
```

### 대사
```yaml
lines:
  - "화자 없는 나레이션"
  - 리아나: "화자가 있는 대사"
  - 속마음: "(내면 독백)"
  - when: "talent.병약"            # 조건부 한 줄
    나레이션: "기침이 멎지 않는다."
  - 리아나:                         # 변형: 가장 구체적인 것이 이긴다
      - "안녕."
      - { when: "talent.혐오스러운분위기", text: "아, 안녕… (한 걸음 물러선다)" }
  - "인라인: {{if rank.liana >= 3}}친구{{else}}동기{{/if}} · 근력 {{stat.근력}}"
```

### 조건식 / 효과식
- 비교 `== != < <= > >=`, 논리 `and or not`, 산술 `+ - * /`, 함수 `min max abs floor`
- 문자열은 `'작은따옴표'` (YAML에서 전체를 `"큰따옴표"`로 감싸기)
- 없는 변수는 0 / 거짓 / 빈 문자열
- 효과: `변수 = 값`, `변수 += 값`, `변수 -= 값`. `stat.X +=`는 `growth.X`만큼 자동 증폭

### 갈림길 / 노트 / 복선
```yaml
# crossroads.yaml
- { id: edric_labyrinth, title: 에드릭의 미궁 실습, key: fate.edric, canon: dead,
    deadline: "1.5.2", weight: 8, canon_event: edric_death_news }
# notes.yaml
- { id: note_edric, title: ..., text: ..., grade: 3, about: [edric_labyrinth] }
# foreshadows.yaml
- { id: F05, title: 리아나가 가슴을 짚음, pending: "2학년 여름" }   # pending = 회수 예정(미작성)
```

## 5. 명령어

| 명령 | 하는 일 |
|---|---|
| `npm run play -- --origin 악역도련님 --perks 고인물의기억 --talents 혐오스러운분위기,만독불침` | 터미널에서 플레이 (`--random 3`이면 무작위 빌드) |
| `npm run lint:story` | 정적 분석 (`--all`이면 정보까지) |
| `npm run sim -- --runs 3000` | 몬테카를로 플레이테스트 → `reports/sim.md` |
| `npm run seek -- "fate.edric == 'saved'" --origin 평민장학생` | 목표까지의 경로 찾기 |
| `npm run verify` | 모든 갈림길 결과의 도달 가능성 자동 증명 |
| `npm test` / `npm run typecheck` | 엔진 테스트 / 타입 검사 |
